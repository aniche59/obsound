PART 3: API GATEWAY ARCHITECTURE (PROFESSOR'S FREQUENT QUESTIONS)
--------------------------------------------------------------------------------

Q: What is an API Gateway, which one are you using, and why?
A: An API Gateway acts as a single reverse-proxy entry point between the frontend 
   client and multiple external backend services.
   In ObSound, our Node.js server (server.js) acts as the API Gateway. All client 
   requests go to /api/* endpoints on our server, which dispatches requests to 
   the appropriate upstream service.

   Why we use an API Gateway:
   1. Security & Key Masking: Private API keys (e.g. LASTFM_API_KEY) stay 
      securely on the server and are never exposed in client browser code.
   2. CORS Resolution: Third-party APIs (Last.fm, iTunes CDN) block cross-origin 
      browser calls. The server-side gateway performs HTTPS calls without CORS.
   3. In-Memory Caching (TTL = 5 mins): Avoids rate-limiting bans and speeds up 
      repeated queries with X-Cache: HIT responses.
   4. Resilience / Fallback: If external APIs are down or blocked, the gateway 
      seamlessly falls back to our offline mock dataset (mockData.js).

A:

PART 4: WHY MONGODB (NOSQL) OVER RELATIONAL SQL (MYSQL/POSTGRESQL)?
--------------------------------------------------------------------------------

1. Polymorphic & Nested Data Structures:
   Each track contains hierarchical acoustic vectors:
   "acousticVectors": {
     "harmonicKey": "D Minor",
     "resonanceFrequency": 528,
     "energyLevel": 9
   }
   In SQL, this would require 3 normalized tables with foreign keys and expensive 
   JOIN operations. In MongoDB, it is stored natively as a single document.

2. Dynamic Array Indexing:
   Tracks have variable-length arrays of user-generated sonic tags:
   "tags": ["wall-of-sound", "shoegaze", "blastbeat"]
   MongoDB natively indexes and queries arrays without requiring junction tables.

3. Rapid Schema Evolution for Underground Music:
   Different underground micro-genres require arbitrary metadata fields 
   (e.g., Bandcamp URLs, cassette catalog codes, tape decay rate). 
   MongoDB's document model allows schema evolution without database table migrations.

4. MongoDB Atlas Cloud Integration:
   ObSound connects to MongoDB Atlas cloud via the connection string:
   mongodb+srv://adityaiche59_db_user:••••••••@cluster0.rc0j9kq.mongodb.net/obsound_nosql_db
   Atlas provides automated 3-node replica sets and high availability.

PART 5: CLIENT-SIDE VS SERVER-SIDE VALIDATION EXPLAINED
--------------------------------------------------------------------------------

- Client-Side Validation (React - react-node-injector.js):
  Provides instantaneous user feedback as the curator types, preventing bad 
  form submissions and reducing unnecessary server bandwidth.

- Server-Side Validation (Node.js - server.js & validator.js):
  Crucial for security. Client-side checks can be bypassed using Postman or cURL. 
  The server inspects every payload, enforces data types and ranges, and rejects 
  malformed input with HTTP 400 Bad Request, protecting the database from corruption.
